# 🐧 Linux Disk Partitioning & Filesystem Creation – fdisk & parted

---

## 📌 0. Lab Setup & Safety

> ⚠️ Always verify the target disk. Partitioning is destructive.

```
lsblk
fdisk -l
```

Sample output:

```
NAME   SIZE TYPE MOUNTPOINT
sda    100G disk
├─sda1  50G part /
└─sda2  50G part /data
sdb    20G  disk   # <— new disk to partition
```

We will use **/dev/sdb**.

---

## 📌 1. Partitioning with fdisk (MBR/GPT interactive)

### 🔹 1.1 Start fdisk

```
sudo fdisk /dev/sdb
```

### 🔹 1.2 Common Commands inside fdisk

| Key | Action                |
| --- | --------------------- |
| m   | help                  |
| p   | print partition table |
| n   | new partition         |
| d   | delete partition      |
| t   | change type           |
| w   | write changes         |
| q   | quit without saving   |

---

### 🔹 1.3 Create a New Partition (Example)

Steps:

```
n        # new partition
p        # primary (or just Enter for default on GPT)
1        # partition number
<Enter>  # default start sector
+5G      # size
w        # write changes
```

### 🔹 1.4 Verify

```
lsblk
```

Output:

```
sdb      20G disk
└─sdb1    5G part
```

---

## 📌 2. Partitioning with parted (Modern, scriptable, GPT-friendly)

### 🔹 2.1 Start parted

```
sudo parted /dev/sdb
```

### 🔹 2.2 Set Label (GPT Recommended)

```
mklabel gpt
```

### 🔹 2.3 Create Partition

```
mkpart primary ext4 0% 5GB
```

### 🔹 2.4 Print Table

```
print
```

### 🔹 2.5 Exit

```
quit
```

---

### 🔹 2.6 Non-interactive (Script Mode)

```
sudo parted -s /dev/sdb mklabel gpt
sudo parted -s /dev/sdb mkpart primary ext4 0% 5GB
```

---

## 📌 3. Create Filesystem (Formatting)

### 🔹 3.1 ext4 Filesystem

```
sudo mkfs.ext4 /dev/sdb1
```

Output:

```
mke2fs ...
Creating filesystem with ... blocks
Writing inode tables: done
```

---

### 🔹 3.2 Other Filesystems

| Filesystem | Command   | Use Case                     |
| ---------- | --------- | ---------------------------- |
| ext4       | mkfs.ext4 | General Linux                |
| xfs        | mkfs.xfs  | Large data, high performance |
| vfat       | mkfs.vfat | USB drives                   |

---

## 📌 4. Mount Filesystem

### 🔹 4.1 Create Mount Point

```
sudo mkdir /data
```

### 🔹 4.2 Mount

```
sudo mount /dev/sdb1 /data
```

### 🔹 4.3 Verify

```
df -h
```

---

## 📌 5. Persistent Mount (/etc/fstab)

### 🔹 5.1 Get UUID

```
blkid /dev/sdb1
```

Output:

```
/dev/sdb1: UUID="abc-123" TYPE="ext4"
```

### 🔹 5.2 Add to fstab

```
UUID=abc-123  /data  ext4  defaults  0  2
```

### 🔹 5.3 Test

```
mount -a
```

---

## 📌 6. fdisk vs parted

| Feature     | fdisk        | parted                |
| ----------- | ------------ | --------------------- |
| Interface   | Interactive  | Interactive + Script  |
| GPT Support | Yes          | Better                |
| Automation  | Limited      | Strong                |
| Recommended | Small/manual | Production/automation |

---

## 📌 7. Real DevOps Scenarios 🔥

### 🔹 Add New Disk to EC2 / VM

1. Attach volume
2. `lsblk` → identify disk
3. `parted` → create partition
4. `mkfs.ext4`
5. Mount + fstab

---

### 🔹 Resize Disk (Basic Idea)

* Extend disk in cloud
* Use `parted` to resize
* Use `resize2fs` (ext4) or `xfs_growfs`

---

## 🚀 Summary

* `fdisk` → manual, interactive
* `parted` → modern, automation-friendly
* `mkfs` → create filesystem
* `mount` + `fstab` → make usable & persistent

👉 This workflow is **core DevOps skill** for storage management.
