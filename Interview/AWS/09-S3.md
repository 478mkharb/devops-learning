# Amazon S3 — Senior DevOps Notes

## 1. S3 mental model

Amazon S3 is **regional object storage**. Objects are stored in buckets and addressed by keys. S3 is commonly used in DevOps for Terraform state, artifacts, logs, backups, AMIs, deployment packages, static websites, and event-driven workflows.

| Concept | Meaning | DevOps relevance |
|---|---|---|
| Bucket | Regional container for objects | State, artifacts, backups, logs |
| Object | Data plus metadata and attributes | Build artifact, release package, log file |
| Key | Object name, including prefix-like path | `releases/v1.2.0/app.zip` |
| Prefix | Key beginning used for logical grouping | `logs/prod/`, `artifacts/` |
| Region | Region where bucket is created | Latency, compliance, DR and cost |
| Storage class | Cost/access profile | Optimize retention and retrieval cost |

> S3 has no real folders. The console displays folders by interpreting prefixes in object keys.

## 2. Bucket, object and key example

```text
s3://company-prod-artifacts/
├── releases/v1.2.0/app.zip
├── releases/v1.2.0/checksums.txt
├── logs/prod/2026/09/application.log
└── backups/postgres/backup-2026-09-14.dump
```

- Bucket: `company-prod-artifacts`
- Object key: `releases/v1.2.0/app.zip`
- Prefix: `releases/v1.2.0/`

## 3. Storage classes

| Storage class | Best fit | Important consideration |
|---|---|---|
| S3 Standard | Frequently accessed data | General-purpose storage |
| Intelligent-Tiering | Unknown or changing access pattern | Automatically moves objects between access tiers; monitoring/automation charges may apply |
| Standard-IA | Infrequently accessed but rapidly needed data | Retrieval charges and minimum storage duration |
| One Zone-IA | Re-creatable infrequent data | Stored in one Availability Zone; not ideal as the only DR copy |
| Glacier Instant Retrieval | Archive data needing immediate retrieval | Retrieval charges and archive constraints |
| Glacier Flexible Retrieval | Archive data with minutes-to-hours retrieval tolerance | Retrieval tier and retrieval time must be selected |
| Glacier Deep Archive | Long-term, rarely accessed retention | Lowest storage cost; longest retrieval time |

### DevOps selection rule

Choose storage class using **access frequency, recovery objective, retention, retrieval time, and total cost**—not storage price alone.

## 4. Lifecycle management

A lifecycle configuration automates object transitions and expiration.

| Action | Purpose | Example |
|---|---|---|
| Transition | Move objects to another storage class | Standard → Glacier Flexible Retrieval after 30 days |
| Expiration | Delete current objects or versions | Delete temporary artifacts after 14 days |
| Noncurrent-version expiration | Remove old versions | Delete noncurrent versions after 90 days |
| Abort incomplete multipart uploads | Remove unfinished uploads | Abort after 7 days |

Lifecycle rules can filter by:

- Prefix
- Object tags
- Object size conditions
- Current or noncurrent object versions

Example policy design:

```text
Build artifacts:
Day 0       → S3 Standard
Day 30      → Standard-IA
Day 90      → Glacier Flexible Retrieval
Day 365     → Expire, if retention permits
```

Do not apply expiration blindly to Terraform state, audit logs, compliance records, or recovery backups.

## 5. Security and access control

### Recommended baseline

| Control | Recommendation |
|---|---|
| Block Public Access | Enable at account and bucket level unless public access is explicitly required |
| Object Ownership | Use `Bucket owner enforced`; avoid ACL-based access control |
| Bucket policy | Use explicit resource-based permissions and conditions |
| IAM | Prefer roles and temporary credentials over access keys |
| Transport | Deny requests where `aws:SecureTransport` is `false` |
| Encryption | Enable default encryption; use SSE-KMS where key control/auditing is required |
| Logging/audit | Use CloudTrail data events where object-level auditing is needed |
| Network path | Use VPC endpoints for private VPC access where appropriate |
| Data exposure | Avoid wildcard principals and broad `s3:*` permissions |

### Bucket policy vs IAM policy

| Policy | Attached to | Main purpose |
|---|---|---|
| Identity-based policy | User, group or role | Grants permissions to an identity |
| Bucket policy | S3 bucket | Grants or denies access to principals for bucket resources |
| SCP | AWS Organizations account/OU | Sets maximum permissions boundary for accounts |
| Permissions boundary | IAM identity | Limits maximum permissions for that identity |

An allow is effective only when all applicable policy controls permit it. An explicit deny overrides an allow.

## 6. Common secure bucket policy conditions

Useful conditions include:

- `aws:SecureTransport` — deny unencrypted transport
- `aws:PrincipalOrgID` — restrict access to an AWS Organization
- `aws:SourceVpce` — restrict access through a specific VPC endpoint
- `aws:SourceIp` — restrict source IP ranges where suitable
- `s3:x-amz-server-side-encryption` — require encryption headers
- `s3:x-amz-server-side-encryption-aws-kms-key-id` — require a specific KMS key

Example deny for non-TLS access:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyInsecureTransport",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:*",
      "Resource": [
        "arn:aws:s3:::company-prod-artifacts",
        "arn:aws:s3:::company-prod-artifacts/*"
      ],
      "Condition": {
        "Bool": {
          "aws:SecureTransport": "false"
        }
      }
    }
  ]
}
```

## 7. Encryption

| Method | Where encryption occurs | Key ownership/control | Typical use |
|---|---|---|---|
| SSE-S3 | S3 | S3-managed keys | Default encryption with low operational overhead |
| SSE-KMS | S3 using KMS | KMS key policy and IAM permissions | Compliance, key separation and auditability |
| DSSE-KMS | S3 with dual-layer KMS encryption | KMS-controlled | Higher protection requirements |
| Client-side encryption | Before upload | Application/customer | Plaintext must never reach S3 |

SSE-KMS normally requires permissions such as `kms:Encrypt`, `kms:Decrypt`, and `kms:GenerateDataKey`, depending on the operation and integration.

> HTTPS protects data in transit. SSE-S3/SSE-KMS protect data at rest. These are separate controls.

## 8. Versioning and Object Lock

| Feature | Versioning | Object Lock |
|---|---|---|
| Main purpose | Preserve object versions | WORM retention protection |
| Recovery from accidental overwrite | Yes | Not its primary purpose |
| Protection from deletion | Limited; delete markers can be created | Yes, during retention/legal hold |
| Legal hold | No | Yes |
| Common DevOps use | Terraform state recovery, artifact rollback | Compliance backups and immutable audit records |

### Object Lock modes

| Mode | Behavior |
|---|---|
| Governance | Authorized users with special permission may bypass retention |
| Compliance | Retention cannot be bypassed until it expires |
| Legal hold | Prevents deletion independently of retention period |

For critical state or backup buckets, combine versioning with carefully designed lifecycle rules. Do not expire noncurrent versions before the required recovery window.

## 9. Replication

| Type | Source and destination | Typical use |
|---|---|---|
| Same-Region Replication | Same AWS Region | Data separation, compliance, processing copies |
| Cross-Region Replication | Different AWS Regions | Disaster recovery and geographic resilience |

Replication design must consider:

- Versioning requirements
- IAM role used by S3 replication
- KMS permissions for encrypted objects
- Replication filters/tags
- Delete-marker behavior
- Replication metrics and failure monitoring
- Whether existing objects require a batch replication process

Replication is not a substitute for backups or recovery testing. A bad deletion or corrupted object can also be replicated.

## 10. Presigned URLs

A presigned URL grants temporary access to a specific S3 operation using the permissions of the signing principal.

| Property | Meaning |
|---|---|
| Temporary | Expires after a configured period or earlier credential expiry |
| Scoped | Usually targets a specific object and operation |
| Credential-free for recipient | Recipient does not need AWS credentials |
| Risk | Anyone possessing the URL can use it until expiry and policy conditions stop it |

Use short expirations, private buckets, least-privilege signing roles, and avoid logging presigned URLs.

## 11. Events and integrations

| Integration | DevOps use |
|---|---|
| SQS | Buffer object events for reliable asynchronous workers |
| SNS | Fan-out notifications to multiple subscribers |
| Lambda | Run processing code after object events |
| EventBridge | Filter and route events to multiple targets |
| CloudTrail | Audit API and, when enabled, object-level activity |
| CloudWatch | Monitor request metrics, errors and replication metrics |

Example:

```text
Developer uploads artifact
        ↓
       S3
        ↓ ObjectCreated event
   EventBridge / SQS
        ↓
 Deployment worker / Lambda
        ↓
 Validation, signing or deployment
```

Design consumers to be **idempotent**. Event delivery can be duplicated, delayed, or processed out of order.

## 12. S3 in DevOps pipelines

### Artifact repository pattern

```text
Git commit
   ↓
CI build and test
   ↓
Create immutable artifact
   ↓
Upload to S3 using versioned key
   ↓
Promote the same artifact across environments
```

Recommended artifact key:

```text
artifacts/<application>/<git-sha>/<artifact-name>
```

Avoid overwriting `latest.zip` as the only release reference. Use immutable keys and maintain a separate deployment manifest or pointer when required.

### Terraform remote state pattern

```text
Terraform
   ↓
S3 backend
   ├── Versioning enabled
   ├── Encryption enabled
   ├── Restricted IAM access
   └── State locking configured using the supported locking mechanism
```

State-bucket requirements:

- Separate state from application artifacts.
- Restrict access to CI/CD and approved operators.
- Enable versioning for recovery.
- Enable encryption.
- Prevent public access.
- Monitor access through CloudTrail where required.
- Do not store secrets in Terraform state unless unavoidable; treat state as sensitive.

## 13. Performance and transfer considerations

| Feature | Purpose |
|---|---|
| Multipart upload | Upload large objects in parts; supports parallelism and recovery |
| Transfer Acceleration | Uses AWS edge locations for long-distance uploads/downloads |
| S3 VPC endpoint | Private access from VPC without traversing the public internet path |
| Prefix distribution | Modern S3 automatically scales request rates; use logical prefixes for organization, not obsolete partitioning assumptions |

Always abort incomplete multipart uploads through lifecycle rules to prevent wasted storage.

## 14. Important S3 limitations and design cautions

- S3 is object storage, not a POSIX filesystem.
- Do not use S3 as a database for frequent in-place updates.
- Object names are keys; renaming generally involves copy plus delete.
- Lifecycle transitions and expiration are asynchronous, not exact-time guarantees.
- Replication is asynchronous.
- A presigned URL is a bearer token.
- Versioning increases storage usage because old versions remain until removed.
- Object Lock requires correct retention design and should be tested before production use.
- Public static website hosting and private CloudFront origin access require different access designs.

## 15. Useful AWS CLI commands

```bash
# List buckets
aws s3 ls

# List objects
aws s3 ls s3://company-prod-artifacts/ --recursive

# Upload
aws s3 cp app.zip s3://company-prod-artifacts/artifacts/app.zip

# Download
aws s3 cp s3://company-prod-artifacts/artifacts/app.zip ./app.zip

# Sync a directory
aws s3 sync ./dist s3://company-prod-artifacts/frontend/

# Inspect bucket location
aws s3api get-bucket-location --bucket company-prod-artifacts

# Inspect versioning
aws s3api get-bucket-versioning --bucket company-prod-artifacts

# Inspect encryption
aws s3api get-bucket-encryption --bucket company-prod-artifacts

# Inspect public-access-block configuration
aws s3api get-public-access-block --bucket company-prod-artifacts

# Inspect lifecycle rules
aws s3api get-bucket-lifecycle-configuration --bucket company-prod-artifacts

# Inspect policy
aws s3api get-bucket-policy --bucket company-prod-artifacts

# Generate a temporary download URL
aws s3 presign s3://company-prod-artifacts/artifacts/app.zip --expires-in 900
```

## 16. Troubleshooting checklist

### `AccessDenied`

1. Confirm the active identity:

   ```bash
   aws sts get-caller-identity
   ```
2. Check identity-based IAM policy.
3. Check bucket policy.
4. Check SCP and permissions boundary.
5. Check explicit denies and conditions.
6. Check KMS key policy for SSE-KMS objects.
7. Check VPC endpoint policy and network path.
8. Check object ownership and ACL assumptions.
9. Check whether the request targets the correct bucket, Region and object key.

### `NoSuchBucket` or wrong Region

- Verify bucket name.
- Check bucket Region.
- Use the correct regional endpoint/profile.
- Confirm the caller has permission to discover/access the bucket.

### Upload succeeds but deployment cannot read artifact

- Verify the deployment role has `s3:GetObject`.
- Verify the artifact key is correct.
- Check KMS `kms:Decrypt` permissions if SSE-KMS is used.
- Check bucket policy conditions and VPC endpoint restrictions.
- Confirm the pipeline is not using a different AWS account or profile.

## 17. Senior DevOps interview questions

### Q1. Why should Terraform state use a dedicated S3 bucket?

State is sensitive infrastructure data. A dedicated bucket allows strict access control, versioning, encryption, auditing, lifecycle and separation from application artifacts.

### Q2. Why is S3 versioning important for Terraform state?

It provides recovery from accidental overwrites or destructive state changes. It does not replace access control, state locking or backup testing.

### Q3. What is the difference between versioning and Object Lock?

Versioning preserves historical versions. Object Lock prevents deletion or overwrite during retention or legal hold.

### Q4. Why is an S3 bucket policy not enough for secure access?

Access is affected by IAM policies, SCPs, permissions boundaries, KMS policies, endpoint policies and explicit denies. Security must be evaluated across all applicable controls.

### Q5. How would you securely expose a private S3 object to a customer?

Keep the bucket private and issue a short-lived presigned URL from a least-privilege backend role. Validate authorization before generating the URL.

### Q6. Why should CI/CD artifacts use immutable keys?

Immutable keys prevent an old deployment from silently changing underneath a running pipeline and improve rollback, traceability and reproducibility.

### Q7. Why is replication not a complete DR strategy?

Replication is asynchronous and can copy unwanted changes or deletions. DR also requires recovery procedures, permissions, application dependencies, DNS strategy and regular recovery testing.

### Q8. How do you prevent public S3 exposure?

Enable Block Public Access, use Bucket owner enforced, keep buckets private, restrict bucket policies, deny insecure transport, scan policies continuously and audit access.

## 18. One-line interview answers

| Question | Short answer |
|---|---|
| What is S3? | Regional, highly durable object storage using buckets and keys. |
| What is a bucket? | A regional container for S3 objects. |
| What is a key? | The unique object name inside a bucket. |
| What is lifecycle? | Automated transition and expiration management. |
| What is versioning? | Retention of multiple object versions under one key. |
| What is Object Lock? | WORM-style retention and legal-hold protection. |
| What is CRR? | Asynchronous replication between Regions. |
| What is SRR? | Asynchronous replication within the same Region. |
| What is SSE-KMS? | S3 encryption at rest controlled through AWS KMS. |
| What is a presigned URL? | Temporary, scoped access without giving AWS credentials to the recipient. |
| Why use S3 for Terraform state? | Durable remote state with controlled access, versioning and encryption. |
