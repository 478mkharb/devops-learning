# 📌 What is a Load Balancer

A **Load Balancer** distributes incoming network traffic across multiple backend targets such as:

* 🖥️ EC2 instances
* 📦 Containers
* 🌐 IP addresses
* ⚡ Lambda functions

### 🎯 Benefits

* ✅ High availability
* 🔁 Fault tolerance
* 📈 Scalability
* ⚡ Improved performance

---

# 🌐 Types of AWS Load Balancers

AWS provides **four types of Elastic Load Balancers (ELB)**:

| Load Balancer                      | OSI Layer   | Protocol Support          | Best For                          |
| ---------------------------------- | ----------- | ------------------------- | --------------------------------- |
| 🚀 Application Load Balancer (ALB) | Layer 7     | HTTP / HTTPS / WebSockets | Web applications & microservices  |
| ⚡ Network Load Balancer (NLB)      | Layer 4     | TCP / UDP / TLS           | Ultra‑high performance networking |
| 🛡️ Gateway Load Balancer (GWLB)   | Layer 3     | IP / GENEVE               | Security appliances               |
| 🏛️ Classic Load Balancer (CLB)    | Layer 4 & 7 | HTTP / HTTPS / TCP        | Legacy applications               |

---

# 🚀 1. Application Load Balancer (ALB)

### 🧭 OSI Layer

**Layer 7 – Application Layer**

### 🔗 Supported Protocols

* HTTP
* HTTPS
* WebSockets

### ⭐ Key Features

* 🔀 Path‑based routing
* 🌍 Host‑based routing
* 📦 Container support
* ⚡ Lambda integration
* 🚀 HTTP/2 support

### 🔄 Load Balancing Algorithm

**Round Robin**

Requests are distributed sequentially across targets.

### 💼 Use Cases

* Microservices architecture
* Kubernetes ingress
* Web applications
* REST APIs

### 🏗️ Example Architecture

```
Users
  |
  v
Application Load Balancer
  |
  |---- EC2 Instance 1
  |---- EC2 Instance 2
  |---- EC2 Instance 3
```

---

# ⚡ 2. Network Load Balancer (NLB)

### 🧭 OSI Layer

**Layer 4 – Transport Layer**

### 🔗 Supported Protocols

* TCP
* UDP
* TLS

### ⭐ Key Features

* ⚡ Extremely low latency
* 🌍 Static IP support
* 📈 Handles millions of requests per second
* 🧾 Preserves client IP

### 🔄 Load Balancing Algorithm

**Flow Hash Algorithm**

Traffic is distributed using a hash based on:

* Source IP
* Source Port
* Destination IP
* Destination Port
* Protocol

### 💼 Use Cases

* 🎮 Gaming servers
* 📡 Real‑time applications
* 💹 High‑frequency trading
* 🌍 IoT backends

### 🏗️ Example Architecture

```
Clients
   |
   v
Network Load Balancer
   |
   |---- EC2 instance (TCP service)
   |---- EC2 instance (TCP service)
```

---

# 🛡️ 3. Gateway Load Balancer (GWLB)

### 🧭 OSI Layer

**Layer 3 – Network Layer**

### 🔗 Supported Protocol

* GENEVE

### 🎯 Purpose

GWLB is designed to deploy and scale **security appliances**.

Examples:

* 🔥 Firewalls
* 🕵️ Intrusion Detection Systems
* 🔍 Deep Packet Inspection

### 🔄 Load Balancing Algorithm

**5‑Tuple Flow Hash**

Traffic distribution based on:

* Source IP
* Destination IP
* Source Port
* Destination Port
* Protocol

### 💼 Use Cases

* 🔥 Network firewalls
* 🛡️ Security inspection
* 🧠 Threat detection systems

### 🏗️ Example Architecture

```
Internet
   |
   v
Gateway Load Balancer
   |
   |---- Firewall Appliance
   |---- IDS Appliance
```

---

# 🏛️ 4. Classic Load Balancer (CLB)

### 🧭 OSI Layer

Layer **4 and Layer 7**

### 🔗 Supported Protocols

* HTTP
* HTTPS
* TCP

### ⚠️ Characteristics

* Legacy load balancer
* Limited routing features
* Used in older AWS architectures

### 🔄 Algorithm

**Round Robin**

### 💼 Use Cases

* Legacy AWS applications
* Older architectures

# 🔄 Load Balancing Algorithms

| Algorithm       | Used By  | Description                            |
| --------------- | -------- | -------------------------------------- |
| 🔁 Round Robin  | ALB, CLB | Requests distributed sequentially      |
| 🔗 Flow Hash    | NLB      | Routing based on connection attributes |
| 🧮 5‑Tuple Hash | GWLB     | Based on IPs, ports and protocol       |

# 🎯 Routing Policies in AWS Load Balancers

Routing policies determine **how incoming traffic is routed to backend targets**.

These policies evaluate request attributes like:

* 🌍 Hostname
* 📁 URL path
* 🧾 HTTP headers
* ❓ Query parameters
* 🌐 Source IP

---

## 🧭 ALB Routing Policy Types

| Routing Policy        | Description                 | Example         | Use Case           |
| --------------------- | --------------------------- | --------------- | ------------------ |
| 🌍 Host‑Based Routing | Routes based on domain name | api.example.com | Microservices      |
| 📁 Path‑Based Routing | Routes based on URL path    | /api/*          | API separation     |
| 🧾 Header Routing     | Routes using HTTP headers   | User‑Agent      | Device routing     |
| ❓ Query Routing       | Based on query parameters   | ?version=v2     | Canary deployments |
| 🌐 Source IP Routing  | Based on client IP          | Office IP range | Security filtering |

---

## 📌 Path‑Based Routing Example

```
User Request
      |
      v
Application Load Balancer
      |
      |--- /api/* ----> API Service
      |
      |--- /images/* -> Image Service
      |
      |--- /shop/* ---> Ecommerce Service
```

# 🍪 Sticky Sessions (Session Affinity)

ALB supports **session persistence** using cookies.

Example:

```
User → ALB → EC2 Instance A
Next Request → EC2 Instance A
```

Used for applications that require **user session persistence**.

---

# ⚖️ Weighted Routing

Traffic can be split between multiple target groups.

| Target Group | Traffic |
| ------------ | ------- |
| Version v1   | 80%     |
| Version v2   | 20%     |

### 🚀 Use Cases

* Blue/Green deployments
* Canary releases
* A/B testing
