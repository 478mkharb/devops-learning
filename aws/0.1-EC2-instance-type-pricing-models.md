# EC2 Instance Naming Convention

Example instance type:

```
m6i.large
```

| Component | Meaning         | Description                                        |
| --------- | --------------- | -------------------------------------------------- |
| **m**     | Instance Family | Defines the category of workload (General Purpose) |
| **6**     | Generation      | 6th generation hardware platform                   |
| **i**     | Processor Type  | Intel based CPU                                    |
| **large** | Instance Size   | Determines vCPU, RAM, and network capacity         |

### Example Breakdown

| Instance     | Meaning                                    |
| ------------ | ------------------------------------------ |
| `m6i.large`  | General purpose, 6th generation, Intel CPU |
| `c7g.xlarge` | Compute optimized, 7th gen, Graviton CPU   |
| `r6g.large`  | Memory optimized, Graviton processor       |

# EC2 Instance Categories

## General Purpose

Balanced compute, memory, and networking.

| Family | Focus              | Characteristics                           | Typical Workloads             |
| ------ | ------------------ | ----------------------------------------- | ----------------------------- |
| **t**  | Burstable CPU      | CPU credit model allows occasional bursts | Dev/Test, small websites      |
| **m**  | Balanced CPU & RAM | General purpose compute                   | Application servers, web apps |

---

## Compute Optimized

Designed for **CPU‑intensive workloads**.

| Family | Focus    | Characteristics             | Typical Workloads                      |
| ------ | -------- | --------------------------- | -------------------------------------- |
| **c**  | High CPU | High performance processors | APIs, gaming servers, batch processing |

---

## Memory Optimized

Optimized for **memory‑intensive applications**.

| Family | Focus                   | Characteristics                | Typical Workloads   |
| ------ | ----------------------- | ------------------------------ | ------------------- |
| **r**  | High memory             | Large RAM capacity             | Redis, Memcached    |
| **x**  | Extra large memory      | Extremely high RAM instances   | SAP HANA            |
| **z**  | High frequency + memory | High single‑thread performance | Financial databases |

---

## Storage Optimized

Designed for **high disk throughput and IOPS workloads**.

| Family | Focus         | Characteristics                  | Typical Workloads    |
| ------ | ------------- | -------------------------------- | -------------------- |
| **i**  | High IOPS SSD | NVMe SSD optimized for heavy I/O | NoSQL, Elasticsearch |
| **d**  | Dense storage | High disk capacity               | Data warehousing     |
| **h**  | HDD storage   | High throughput HDD              | Log processing       |

# Accelerated Computing

Instances that use **specialized hardware accelerators**.

| Family  | Hardware       | Characteristics              | Typical Workloads      |
| ------- | -------------- | ---------------------------- | ---------------------- |
| **p**   | GPU            | High performance GPUs        | AI / ML training       |
| **g**   | GPU (graphics) | GPU optimized for rendering  | Video rendering        |
| **f**   | FPGA           | Custom hardware acceleration | Specialized workloads  |
| **inf** | Inferentia     | Optimized for ML inference   | AI prediction services |
| **trn** | Trainium       | Optimized for ML training    | Deep learning models   |

# EC2 Pricing Models

| Pricing Model           | Cost Level | Flexibility | Commitment | Description                                     | Typical Use Case     |
| ----------------------- | ---------- | ----------- | ---------- | ----------------------------------------------- | -------------------- |
| **On‑Demand**           | High       | Very High   | None       | Pay per second/hour                             | Short‑term workloads |
| **Reserved Instances**  | Low        | Medium      | 1–3 years  | Discount for long‑term commitment               | Production workloads |
| **Savings Plans**       | Low        | High        | 1–3 years  | Flexible pricing across compute services        | Mixed workloads      |
| **Spot Instances**      | Very Low   | Low         | None       | Uses spare AWS capacity (can terminate anytime) | Batch jobs, CI/CD    |
| **Dedicated Instances** | High       | Low         | Optional   | Hardware dedicated to single customer           | Compliance workloads |
| **Dedicated Hosts**     | Very High  | Very Low    | Optional   | Physical server dedicated to your account       | BYOL licensing       |

# Dedicated Instances vs Dedicated Hosts

| Feature                       | Dedicated Instances  | Dedicated Hosts      |
| ----------------------------- | -------------------- | -------------------- |
| Hardware Isolation            | Yes                  | Yes                  |
| Physical Server Visibility    | No                   | Yes                  |
| Control Over Hardware         | Limited              | Full control         |
| Bring Your Own License (BYOL) | Limited support      | Fully supported      |
| Typical Use Case              | Compliance workloads | Enterprise licensing |

# Notes for DevOps Engineers

* Choose **t instances** for low‑traffic or development environments.
* Use **m instances** for most application servers.
* Use **c instances** when CPU is the bottleneck.
* Use **r/x instances** for in‑memory databases.
* Use **i/d/h instances** for heavy storage workloads.
* Use **Spot Instances** to reduce cost for fault‑tolerant jobs.
