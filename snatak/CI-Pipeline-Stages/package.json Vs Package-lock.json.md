# Understanding `package.json`, `package-lock.json`, `npm install`, and `npm ci`

## 1. package.json

- Created by the developer.
- Contains project information and dependency requirements.
- Specifies **what packages** the project needs.
- Dependency versions can be:
  - Exact (`"axios": "1.8.2"`)
  - Flexible (`"axios": "^1.8.2"`)

Example:

```json
{
  "dependencies": {
    "axios": "^1.8.2"
  }
}
```

---

## 2. package-lock.json

- Automatically generated by npm.
- Records the **exact versions** of all installed packages.
- Includes direct and transitive (nested) dependencies.
- Ensures every developer and CI server installs the same dependency tree.

---

# npm install

## What it does

- Reads `package.json`
- Reads `package-lock.json` (if it exists)
- Resolves dependencies
- Creates or updates `package-lock.json`
- Installs dependencies into `node_modules`

### Best for

- Local development
- Adding or updating dependencies

Example:

```bash
npm install
```

---

# npm ci

## What it does

- Reads `package.json`
- Requires `package-lock.json`
- Deletes existing `node_modules`
- Installs the exact versions from `package-lock.json`
- Never updates `package-lock.json`

### Best for

- Jenkins
- GitHub Actions
- GitLab CI
- Production builds

Example:

```bash
npm ci
```

---

# Example

Suppose `package.json` contains:

```json
{
  "dependencies": {
    "express": "^4.18.0"
  }
}
```

### Using `npm install`

Today:

```
express 4.18.2
```

Next month:

```
express 4.18.4
```

A newer compatible version may be installed.

---

### Using `npm ci`

Even if a newer version exists, npm installs:

```
express 4.18.2
```

because it is locked in `package-lock.json`.

---

# Why package-lock.json is still needed even with exact versions

Suppose:

```json
{
  "dependencies": {
    "express": "4.18.2"
  }
}
```

You have locked **express**, but express has its own dependencies.

```
Your Project
      │
      ▼
 express 4.18.2
      │
      ├── body-parser
      ├── cookie
      ├── debug
      └── send
```

Those packages also have their own dependencies.

`package-lock.json` locks **the entire dependency tree**, not just the packages listed in `package.json`.

---

# Comparison

| Feature | npm install | npm ci |
|----------|-------------|---------|
| Reads package.json | ✅ | ✅ |
| Reads package-lock.json | ✅ | ✅ (Required) |
| Creates package-lock.json | ✅ | ❌ |
| Updates package-lock.json | ✅ | ❌ |
| Deletes node_modules first | ❌ | ✅ |
| Installs exact locked versions | Usually | ✅ Always |
| Faster | ❌ | ✅ |
| Best for | Development | CI/CD |

# How `package.json` and `package-lock.json` are Created

## Step 1: Create a Node.js project

Run:

```bash
npm init
```

or

```bash
npm init -y
```

This creates:

```
package.json
```

---

## Step 2: Install dependencies

Run:

```bash
npm install express
```

or

```bash
npm install
```

If `package-lock.json` does not exist, **`npm install` automatically creates it** along with the `node_modules` directory.

Files created:

```
package-lock.json
node_modules/
```

---

## What about `npm ci`?

- **`npm ci` does NOT create `package-lock.json`.**
- It **requires** an existing `package-lock.json`.
- If the lock file is missing, `npm ci` fails with an error.

Example:

```bash
npm ci
```

Output:

```text
npm ERR! The npm ci command can only install with an existing package-lock.json
```

---

## Summary

| Command | Result |
|----------|--------|
| `npm init` | Creates `package.json` |
| First `npm install` | Creates `package-lock.json` and `node_modules` |
| `npm ci` | Uses existing `package-lock.json` (does **not** create or update it) |

### Simple Flow

```text
npm init
    │
    ▼
package.json
    │
npm install
    │
    ▼
package-lock.json
node_modules/
    │
Commit both files to Git
    │
    ▼
CI/CD (Jenkins)
    │
npm ci
    │
    ▼
Installs exact dependencies
(No new package-lock.json is created)
```
