# Understanding `package.json`, `package-lock.json`, `npm install`, and `npm ci`

## 1. package.json

- Created by the developer.
- Contains project information and dependency requirements.
- Specifies **what packages** the project needs.
- Dependency versions can be:
  - Exact (`"axios": "1.8.2"`)
  - Flexible (`"axios": "^1.8.2"`)

Example:

```json
{
  "dependencies": {
    "axios": "^1.8.2"
  }
}
```

---

## 2. package-lock.json

- Automatically generated by npm.
- Records the **exact versions** of all installed packages.
- Includes direct and transitive (nested) dependencies.
- Ensures every developer and CI server installs the same dependency tree.

---

# npm install

## What it does

- Reads `package.json`
- Reads `package-lock.json` (if it exists)
- Resolves dependencies
- Creates or updates `package-lock.json`
- Installs dependencies into `node_modules`

### Best for

- Local development
- Adding or updating dependencies

Example:

```bash
npm install
```

---

# npm ci

## What it does

- Reads `package.json`
- Requires `package-lock.json`
- Deletes existing `node_modules`
- Installs the exact versions from `package-lock.json`
- Never updates `package-lock.json`

### Best for

- Jenkins
- GitHub Actions
- GitLab CI
- Production builds

Example:

```bash
npm ci
```

---

# Example

Suppose `package.json` contains:

```json
{
  "dependencies": {
    "express": "^4.18.0"
  }
}
```

### Using `npm install`

Today:

```
express 4.18.2
```

Next month:

```
express 4.18.4
```

A newer compatible version may be installed.

---

### Using `npm ci`

Even if a newer version exists, npm installs:

```
express 4.18.2
```

because it is locked in `package-lock.json`.

---

# Why package-lock.json is still needed even with exact versions

Suppose:

```json
{
  "dependencies": {
    "express": "4.18.2"
  }
}
```

You have locked **express**, but express has its own dependencies.

```
Your Project
      │
      ▼
 express 4.18.2
      │
      ├── body-parser
      ├── cookie
      ├── debug
      └── send
```

Those packages also have their own dependencies.

`package-lock.json` locks **the entire dependency tree**, not just the packages listed in `package.json`.

---

# Comparison

| Feature | npm install | npm ci |
|----------|-------------|---------|
| Reads package.json | ✅ | ✅ |
| Reads package-lock.json | ✅ | ✅ (Required) |
| Creates package-lock.json | ✅ | ❌ |
| Updates package-lock.json | ✅ | ❌ |
| Deletes node_modules first | ❌ | ✅ |
| Installs exact locked versions | Usually | ✅ Always |
| Faster | ❌ | ✅ |
| Best for | Development | CI/CD |

# Easy Way to Remember

## package.json

**Shopping List**

```
Need:
- Express
- React
- Axios
```

## package-lock.json

**Shopping Bill**

```
Bought:
- Express 4.18.2
- React 18.2.0
- Axios 1.8.2
- All nested dependencies
```

---

## npm install

> "Install the required packages and update the shopping bill if needed."

---

## npm ci

> "Throw away the old packages and install exactly what is written in the shopping bill."
